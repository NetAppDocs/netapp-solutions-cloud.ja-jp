Google Cloud NetApp Volumes は、 NFS および SMB 共有を提供するために複数の TCP ポートを公開します。

* https://docs.cloud.google.com/netapp/volumes/docs/connect-clients/connect-nfs-clients#firewall_rules_for_nfs_volumes_access["NFS アクセスに必要なポート"^]
* https://docs.cloud.google.com/netapp/volumes/docs/connect-clients/connect-smb-clients#firewall_rules_for_smb_volumes_access["SMBアクセスに必要なポート"^]


さらに、SMB、Kerberosを含むLDAPを使用したNFS、およびデュアルプロトコル構成では、Windows Active Directoryドメインへのアクセスが必要です。Active Directory接続は、リージョンごとに https://docs.cloud.google.com/netapp/volumes/docs/configure-and-use/active-directory/create-ad-policy["構成された"^]する必要があります。Active Directoryドメインコントローラ（DC）は、指定されたDNSサーバと https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/7fcdce70-5205-44d6-9c3a-260e616a2f04["DNSベースのDC検出"^]を使用して識別されます。返されたDCのいずれかが使用されます。対象となるDCのリストは、Active Directoryサイトを指定することで制限できます。

Google Cloud NetApp Volumes は、 https://docs.cloud.google.com/netapp/volumes/docs/plan-and-prepare/networking#configure_private_services_access["Google Cloud NetApp Volumesのオンボーディング"^]中に `gcloud compute address`コマンドで割り当てられた CIDR 範囲の IP アドレスを使用して接続します。この CIDR をソースアドレスとして使用し、Active Directory ドメインコントローラへのインバウンドファイアウォールを設定できます。

Active Directoryドメインコントローラは https://docs.cloud.google.com/netapp/volumes/docs/plan-and-prepare/security-considerations["ここで述べたように、ポートをGoogle Cloud NetApp Volumes CIDR に公開します。"^]する必要があります。
